之前按「贝勒德」去查的 boss，TMS 实名叫 培羅德，且它和 貝倫(Vellum 金龙) 是两个不同 boss：
  • 貝倫 = Vellum（金龙）：8930100 / 9210015(普通) / 9210016(混沌) / 9303158 / 9390307 / 9410273(終極武器貝倫MK2)…
  • 培羅德 = 另一个 Boss遠征隊(自动组队挑战) 多部位 boss，入口 NPC 渥雷納(Wurena)。实据：TMS Skill.img.json 含「[BOSS對象 : 培羅德]」「渥雷納的信賴：培羅德」「完成培羅德殲滅任務」。
本报告的 Boss 副本部分按 培羅德 为准。若你其实想要 Vellum(貝倫)，那是另一个金龙 boss，可另行评估。

A. 岩壁巨人 克洛宿斯 → 做成可重复

现状：一次性 Theme Dungeon（主题副本）

经用户纠正与实测确认，岩壁巨人本质不是可重复副本，而是主題副本(Theme Dungeon)=一次性剧情：

  • TMS 任务 1340 = [主題副本] 岩壁巨人 克洛宿斯
  • 后续 31330 – 31355 是连续剧情链（救援作戰 1–7 等），与「黃昏的勇士之村」同类
  • 地图/怪物/NPC 资源齐备（见下），卡住它“不可重复”的只是入口与剧情锁，不是资源

资源清单（TMS 全段实测，已具备）

项目数量 / 值说明
地图30 张24009 段 + 924030000 实例图
新怪物14 种含 Boss 8800400 5700万HP / Lv165
新 NPC17 个剧情/功能 NPC
任务27 个1340 主线 + 31330–31355 链
骑乘图(fieldType=6)BeiDou 现有 302 张立体 Boss 机制所需的骑乘图老端已支撑
等级带150–165远低于职业/等级上限 255，无门槛冲突

怪物数据已用 dotnet MSProbe.dll Packs/Mob_00000.ms 实测提取成功（勿用 MapleStory-IMG/Data/Mob/，那里只有 _Canvas 无 info）。

改造为「可重复」的要点

  • 解剧情锁：把主题副本的「一次性进入」改为可重复入口（仿 CWKPQ.js/LudiPQ.js 的 EventInstanceManager 进入条件，去掉「已完成则不再开放」的判定）。
  • 三段推进自建：爬臂 → 钻体 → 打心 的立体 Boss 流程，老端无现成脚本，需在 event 实例里自己编排（阶段切换、部件刷新、进入体内图）。
  • Boss 招式 / 掉落自写：8800400 的技能组与掉落表 TMS 客户端不含（机制还原，非数值），需按手感补一套。
  • 必带刷怪修复：副本实例图没有周期刷怪，mobTime=0 的怪清一次不回 ⇒ event 脚本必须 eim.schedule(fn,5000) + map.instanceMapRespawn()（仓库 41 个 PQ 脚本已如此）。
结论 A：可重复化可行，还原度 ≈ 85%（资源齐、机制老端可表达）
瓶颈不在数据，而在「把一次性剧情副本改写成可重复 PQ 实例 + 补 Boss 招式/掉落」。属中工作量自建，建议排期在 CWKPQ 段 / 龍騎士 / 夏摩斯之后。

B. 培羅德 Boss 副本（TMS 实名）

1. 战斗机制：多部位破坏型 Boss

培羅德是 Boss遠征隊（自动组队挑战） 系统的 boss，核心玩法是破坏多个身体部位才算击破。其专属部件：

部位怪物 ID备注
培羅德的頭（头）9390600 / 9390601 / 93906023 个变体
培羅德的右肩（右肩）9390610
培羅德的左肩（左肩）9390611
培羅德的腹部（腹）9390612
培羅德的豆芽花（芽）9390636 / 9390637 / 93906383 个变体

注：93906xx 是多个远征 boss 共用的部件块——同块里还有 死亡伯爵替身(9390603)、肩膀/下半身魔王廣域攻擊用替身(9390613-619)、墮落貝伊派普/偉德雷/菲迪特(9390620-646) 等。培羅德只占用其中頭/肩/腹/芽 5 类部件。

2. BeiDou 现状：完全缺失 + 无远征框架

核实项结果
客户端怪物名（clien/Data/String/Mob.img，2419 条）无 培羅德 / 貝倫 / 任何 93906xx 部件
客户端 NPC（clien/Data/String/Npc.img，2366 条）无 渥雷納(Wurena) 入口 NPC
服务端 Java Expedition 类无 Boss遠征隊 / 远征框架
可承接的框架有 EventInstanceManager(PQ) + AreaBoss 脚本（仿 CWKPQ/LudiPQ 单竞技场战）

⇒ 培羅德在 BeiDou 是从零开始，连美术资源都要从 TMS 搬（MSProbe 提取）或复用现有 boss 精灵。

3. 迁移方案（自建单竞技场 Boss 战）

  • 场地：新建 1 张普通竞技场图（无需 fieldType=6 骑乘，普通 field 即可）。
  • 怪物：用 MSProbe 提取 9390600–9390638 等部件数值（HP/Lv/技能组），或复用现有 boss 立绘替代。
  • 脚本（PQ / event 实例）：进场 → 同时刷 5 个部位 → 破坏逻辑（全破坏=击破；或部位 HP 汇总为主 HP）→ 周期性召唤小怪（菲迪特/偉德雷/貝伊派普）+ 廣域攻擊用替身 → 掉落 / 殲滅任務判定。
  • 入口 NPC：新增 渥雷納（或复用现有 NPC 当远征入口）。
  • 奖励：掉落与 殲滅任務 奖励自定义（TMS 客户端不含数值，按手感配）。
还原度天花板（必须接受）
TMS 的 Boss遠征隊 UI（自动组队队列、里程、渥雷納信任系统）是 273 专属系统，083 老端无法渲染。 这些不能 1:1 还原，只能简化替代：自动组队 → 改为手动组队进 PQ；里程/信任 → 改为普通击杀计数或副本积分（已有 extend_value 货币机制可复用）。 战斗本身的「多部位破坏」机制老端可表达，是还原重点。
结论 B：可迁移，但需完全自建（与 Colossus 同级）
可行，工作量高于岩壁巨人（连怪物资源都要搬 + 多部位破坏逻辑 + 没有远征 UI 兜底）。建议排在岩壁巨人之后。
