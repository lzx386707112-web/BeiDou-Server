# 时装暖暖发色崩溃修复设计

## 背景

“时装暖暖”点击“发色”后会进入 `发色选择.js`。该脚本目前通过
`cm.itemExists()` 判断当前发型的其他颜色是否存在，然后把结果交给
`cm.sendStyle()` 做图片预览。

`cm.itemExists()` 只依据 `String.wz` 中是否存在名称记录。发型资源精简后，
部分名称记录仍然存在，但对应客户端 Hair IMG 已被移除。因此脚本会把无效
发型 ID 发送给旧客户端，客户端在渲染预览时崩溃。

## 目标

- 当前发型没有可用发色时显示明确提示，不发送发型预览封包。
- 当前发型属于保留目录时，继续展示可用的 0–7 色，并维持现有 6000 点券价格。
- 不修改其他美容、NPC 对话或全局物品存在性逻辑。

## 方案

在 `发色选择.js` 中使用 `ItemConstants.isNewHair()` 作为发型资源的权威白名单。
该方法读取当前仓库维护的 `hair-base-ids.txt`，其内容与实际保留的客户端发型
家族对应。

发色展示流程如下：

1. 由角色当前发型计算十位基准 ID。
2. 若当前发型不在保留白名单中，发送“该发型不支持改变颜色，请先更换发型”
   提示并结束对话。
3. 仅把同时满足白名单校验、名称记录存在且不是当前已装备颜色的 ID 放入预览列表。
4. 若过滤后列表为空，同样发送提示并结束对话；否则调用 `sendStyle()`。
5. 玩家提交选择时保留现有索引范围校验、点券校验、扣费和 `setHair()` 流程。

## 错误处理

所有无效或无可选颜色的情况都在调用 `sendStyle()` 前结束。这样客户端不会收到
缺少资源的发型 ID，也不会因为空列表或越界选择而崩溃。提示路径不扣除点券。

## 测试

新增针对脚本的静态契约测试，至少验证：

- 脚本使用 `ItemConstants.isNewHair()` 校验当前发型和候选发色。
- 无效当前发型走提示分支，并在 `sendStyle()` 前返回。
- 预览列表为空时只提示、不发送预览。
- 有效发型仍只枚举颜色位 0–7。
- 既有选择索引和点券校验保持存在。

运行目标测试，并检查最终差异只包含本次脚本修复、对应测试和设计说明。
