# 神秘河经验、掉落与任务启用设计

## 目标

让 163 级等未满级角色击杀神秘河怪物时获得 TMS 对应经验，让普通掉落与任务掉落在部署后实际生效，并让已迁移的 23 个旧端兼容神秘河任务能够闭环完成。

## 已确认事实

- 当前服务端神秘河怪物 XML 已包含经验值。抽样怪物 `8641000`、`8642000`、`8643000`、`8644000`、`8644509` 与 TMS 的经验分别一致为 `98708`、`248003`、`349836`、`393361`、`553217`。
- 本机数据库的 Flyway 历史停在 `2.1.34`，没有执行 `V2.1.42__add_arcane_river_mob_and_quest_drops.sql`，神秘河怪物在 `drop_data` 中的记录数为 0。
- Maven 会将 `src/main/resources` 放入 JAR。SQL 在打包时只被复制，必须在新 JAR 启动并连接数据库后才由 Flyway 执行。
- 23 个神秘河任务及其 Quest、Item、String 数据已经迁移到客户端和服务端。
- 神秘河任务号 `341xx–345xx` 超过 Java 有符号 `short` 的上限。任务请求封包已经改为无符号读取，但怪物掉落链路仍通过 `short questid` 和 `ResultSet#getShort` 读取，任务掉落会溢出为负数。

## 设计

### 经验

保留 TMS 原始怪物经验，不重新估算或统一倍率。增加一个针对性契约检查，验证所有实际出现在神秘河地图中的怪物都存在服务端 XML、经验字段为正数，并对代表怪物验证与 TMS 来源一致。运行时仍使用现有 `LifeFactory -> MonsterStats -> Monster.distributeExperience -> Character.gainExp` 链路。

后续调查发现本服 `qst_max_level` 仍为 120；骑士团角色达到 163 级时，`Character.gainExpInternal` 会跳过等级高于职业上限的角色，因此经验完全不发放。按用户确认，将冒险家和骑士团的四转最高等级统一提升为 250；经验表已经覆盖到 250，不修改全局经验倍率。

### 普通掉落

保留 `V2.1.42` 作为唯一掉落数据来源。迁移为 83 种实际刷新的神秘河怪物补充金币、超级药水 `2000005`、特殊药水 `2000006`，并补充 8 条按任务限制的任务物品掉落。

不新增重复的 `V2.1.43`，也不在 Java 中硬编码兜底掉落。验证阶段检查 SQL 可被 Flyway 识别、打包后位于 JAR 的 `BOOT-INF/classes/db/migration/`，并在测试数据库或可回滚验证库中确认执行后行数与关键记录正确。部署说明明确要求启动新 JAR；仅打包不会执行迁移。

### 任务掉落类型

将怪物掉落链路中的任务号统一为 `int`：普通怪物掉落实体、全局掉落实体、JDBC 读取、地图掉落生成及相关方法参数不再截断为 `short`。低编号旧任务保持原值，`341xx–345xx` 可以与角色任务状态正确匹配。

修改只覆盖任务号的内部表示，不改变客户端封包宽度。客户端任务请求继续将 16 位字段按无符号数解释为 `0–65535`。

### 神秘河任务

启用并验证现有 23 个旧端兼容任务，不扩大为完整现代主线：

- 消逝的旅途 `34102–34105`
- 啾啾艾尔兰 `34203`
- 拉契尔恩 `34303`、`34304`、`34312–34315`
- 阿尔卡娜 `34474`
- 魔菈斯 `34250`、`34252`、`34256`、`34265`
- 艾斯佩拉 `34568`、`34572`、`34574`、`34576`、`34578`、`34582`、`34584`

验证任务的客户端四个 Quest IMG、服务端两套 Quest XML、NPC、目标怪物、8 个任务物品、任务限制掉落及完成奖励形成静态闭包。

## 验证标准

- 代表怪物及全部地图实际怪物的服务端经验字段为正，TMS 抽样值一致。
- 掉落任务号 `34102`、`34584` 经过数据库读取和掉落实体后仍为正整数原值。
- `V2.1.42` 被打入 JAR，Flyway 执行后 83 种怪物均有普通掉落，8 条任务掉落的任务号与任务数据一致。
- 23 个任务的客户端、服务端、NPC、怪物与物品依赖检查全部通过。
- 旧任务号和非神秘河掉落行为不变。

## 非目标

- 不移植依赖现代演出、自动接取、缺失地图或缺失 NPC 的完整 TMS 神秘河主线。
- 不修改经验表、全局经验倍率或全部怪物掉落架构。
- 不覆盖或整理当前工作区中与本问题无关的已有改动。
