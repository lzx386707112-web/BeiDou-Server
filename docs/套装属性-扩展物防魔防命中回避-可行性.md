结论先行：**能加，但要分三层拆开看。只改白名单等于「面板多个数字、实战零效果」，而且客户端会把它显示成"属性"。**

## 当前进度（2026-09-29 更新）

| 层 | 状态 |
| --- | --- |
| 一、后台白名单（服务端 + 前端） | ✅ **已放行** `PDD/MDD/ACC/EVA`（`SUPPORTED_STAT_KEYS` 13 → 17，前端 `SET_ITEM_STAT_KEYS` 同步） |
| 四、客户端面板标签 | ✅ **已完成**，见 `tool/client-debug/BeiDouSetItemCompat/README-stat-labels.md`（4 个中文标签 + 4 个比较分支 + 9 条重定位） |

也就是说：**现在可以在后台配出这 4 个属性、游戏里面板会正确显示 物理防御力/魔法防御力/命中率/回避率，但战斗数值不会变化**，直到走完第三节的 BuffStat 通道。

## 一、后台白名单层（易，1 处 Java + 1 处前端）

`SetItemManager.STAT_KEYS`（24 项，`SetItemManager.java:24`）其实**早就预留了**这些名字：

```
PDD, MDD, ACC, EVA, SPD, JMP, AllStatPct, HPpct, MPpct, StatusRes, BuffDuration
```

但真正做校验的白名单 `SUPPORTED_STAT_KEYS`（同文件 `:30`）只有 13 项：
`STR DEX INT LUK PAD MAD HP MP FinalDamage BossDamage ExpRate DropRate MesoRate`。

三处会直接拒绝并抛 `不支持的套装属性: <key>`：

| 位置 | 作用 |
| --- | --- |
| `SetItemConfigService.java:182` | `update()` 保存档位属性 |
| `SetItemConfigService.java:280` | `sanitizeBonuses()` 读库时过滤 |
| `SetItemConfigService.java:402` | `buildDefinition()` 新建自定义套装 |

前端同样只有 13 项：`gms-ui/src/api/setItem.ts:3` 的 `SET_ITEM_STAT_KEYS`
（`index.vue:407` 用它过滤、`SetItemCreateModal.vue:296` 用它当下拉选项）。

> 数值上限走 `validateValue`：`PDD/MDD/ACC/EVA` 不以 `rate/pct` 结尾、也不是
> `finaldamage/bossdamage/statusres/buffduration`，所以按 flat 处理，范围 `0 ~ 1_000_000`。

## 二、服务端生效层（这才是关键）

`Character.reapplyLocalStats()`（`Character.java:7613-7639`）目前只把 8 个键吃进去：

```java
localMaxHp += setItemBonus.get("HP");   localMaxMp += setItemBonus.get("MP");
localstr/dex/int_/luk += ...("STR"/"DEX"/"INT"/"LUK");
localwatk += ...("PAD");   localmagic += ...("MAD");
```

其余分流：`FinalDamage`/`BossDamage` → `SetItemManager.applyDamage`（挂在 `MapleMap.java:1522`）；
`ExpRate`/`DropRate`/`MesoRate` → `getExpRate()/getDropRate()/getMesoRate()`。

`PDD/MDD/ACC/EVA` 目前**没有任何消费点**：

- `Character` 里没有 `getTotalWdef()/getTotalMdef()/getTotalAcc()/getTotalEva()`。
- `org.gms.client.Stat` 枚举只有 20 项（`SKIN…GACHAEXP`），**没有 WATK/WDEF/MATK/MDEF/ACC/AVOID/SPEED/JUMP**。
  v83 的 `STAT_CHANGED` 位掩码里本来也没有这些字段（那是大巨变之后才加进 `CharacterStat` 的），
  所以**不能**靠"角色属性更新包"把防御/命中/回避推给客户端。

而伤害承担是**客户端权威**的：`TakeDamageHandler.handlePacket` 直接 `p.readInt()` 读客户端发来的
`damage` 就落到 `addHP`，服务端不做防御减免计算。打怪方向同理——服务端只用
`AbstractDealDamageHandler:843-901` 的 `calcDmgMax`（由 `getTotalWatk()/getTotalStr()/...` 算出）
做**上限校验**，这正是现有 `PAD/STR` 套装加成"有效"的真实机制：拉高上限，让客户端算出的高伤害通过校验。

→ **推论：放开白名单后，PDD/MDD/ACC/EVA 只会进 JSON、进面板数据，打怪和挨打都不会变。**
要真生效只有一条通道：**BuffStat**。

## 三、真生效的唯一可行通道：BuffStat

本仓库 `BuffStat` 里这些位都在，且旧端客户端会把它们加进自身的属性/战斗计算
（原版就是靠它们做「铁壁 / 集中术 / 幸运术 / 疾风步」这类技能）：

| BuffStat | 位 |
| --- | --- |
| `WDEF` | `0x200000000` |
| `MDEF` | `0x800000000` |
| `ACC` | `0x1000000000` |
| `AVOID` | `0x2000000000` |
| `SPEED` | `0x8000000000` |
| `JUMP` | `0x10000000000` |
| `WATK` | `0x100000000` |

做法：给装备了套装的角色挂一个"内部套装 buff"，把合计值按 `BuffStat.WDEF/MDEF/ACC/AVOID` 下发，
套装变化 / 上线 / 换装时刷新。代价：要处理 buff 图标显示、与真实 buff 的叠加/覆盖、掉线重连恢复。
`SetItemManager.Bonus` 内部是 `Map<String,Integer>` 累加，取值直接用 `chr.getSetItemBonus("PDD")` 即可。

## 四、客户端面板标签（要改 DLL）

套装面板由 `clien/BeiDouSetItemCompat.dll` 绘制。反汇编标签解析函数（`.text+0x3501 ~ 0x3678`，
ImageBase `0x65c80000`）得到完整逻辑：

**第 1 步 — 决定数值后缀**（`.text+0x3507 ~ 0x3571`）：

- key **包含** `Damage` / `Rate` / `Pct`（子串搜索，helper `0x111e`）→ 后缀 `%`；
- 或 key **精确等于** `StatusRes` / `BuffDuration`（`lstrcmpA`，IAT 槽 `0x65f900f4`）→ 后缀 `%`；
- 否则后缀为空串。

**第 2 步 — 决定中文标签**（`.text+0x3591 ~ 0x3678`，`lstrcmpA` 精确匹配，9 个分支）：

| key | 标签 |
| --- | --- |
| `PAD` | 攻击力 |
| `MAD` | 魔法攻击力 |
| `HP` | 最大HP |
| `MP` | 最大MP |
| `FinalDamage` | 最终伤害 |
| `BossDamage` | Boss伤害 |
| `ExpRate` | 经验获得 |
| `DropRate` | 掉落率 |
| `MesoRate` | 金币获得 |
| **其它任何 key** | **属性**（兜底，`.text+0x3673: cmovne eax, edx`） |

渲染格式串是 `%s +%d%s`（文件偏移 `0x3c14`）。

**DLL 里没有「物理/防御/命中/回避」任何字样**，也没有 `PDD/MDD/ACC/EVA/STR/DEX/INT/LUK`
这些 key 字符串（已用 UTF-16LE / ASCII 双向定向搜索确认）。

→ 后果：
1. 新增 `PDD/MDD/ACC/EVA` 后，游戏内会显示成 **四行一模一样的「属性 +N」**。
2. 现有 `STR/DEX/INT/LUK` 也是走这个兜底、同样显示成「属性」——可以在游戏里核对面板印证。
3. 要正确显示，必须给该 DLL 加 4 个标签 + 4 个比较分支。本仓库已有这条流水线
   （`tool/client-debug/BeiDouSetItemCompat/` 下的 `patch_*.py` + `fix_dll_reloc_hygiene.py`
   + 契约测试），但改 `.rdata`/`.text` 必须走生成器重建、并检查重定位僵尸条目。

## 五、建议的两条路线

**路线 A（只放开白名单，半小时）**：改 `SUPPORTED_STAT_KEYS` + 前端 `SET_ITEM_STAT_KEYS`。
适合"我只想让面板能配这几个数值，不指望真加成"。代价：显示成「属性」，且实战无效。

**路线 B（真生效，需三件事一起做）**：
1. 白名单 + 前端下拉放开 4 个键；
2. 服务端加内部套装 buff，按 `BuffStat.WDEF/MDEF/ACC/AVOID` 下发并在套装变更时刷新；
3. DLL 补丁加 4 个中文标签 + 4 个精确匹配分支（走生成器 + 契约测试）。

未决点：PDD/MDD 走 buff 会不会和真实防御类 buff（铁壁等）互相覆盖，需要先定叠加规则。
