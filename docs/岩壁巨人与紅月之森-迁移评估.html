1.6 能不能「完整」迁移：逐项判定

要素判定依据 / 缺口
地图美术与地形可迁30 张 TMS 地图可解析；与已迁过的神秘河/黃昏同类型，走既有地图迁移流程。
骑乘图 (fieldType=6)可迁BeiDou 现有地图里 302 张 ft=6，老端本来就支持；timeLimit=5 的强制传送行为需实机确认一次。

怪物数据可得Packs/Mob_00000.ms 实测可提取（含 info + 动画）；迁移走 arc.clone_image + sanitize_mob，画布统一 ARGB4444。
NPC 数据可得MapleStory-IMG/Data/Npc/2210000.img 等存在。
任务链可迁27 条任务按现有导入规范（QuestInfo 只留 name/area/0/1/2，Say 留空，剥 startscript/endscript）；不写过场照样能接能交。
副本流程脚本需自写TMS 客户端不含任何 .js，colossus / colossus2 / 240092100_enter / enter_924030000 的逻辑要自己实现（打手臂 → 体内 → 心脏阶段推进）。
Boss 招式与时序需自配8800400 有 attack1–4 + skill1，但招式时序/伤害/掉落都在服务端，TMS 客户端没有；要按 BeiDou 现有 Boss 的配置方式自配。
过场对话 / 剧情演出放弃与既定「无过场」策略一致；用任务文本代替。
掉落与奖励需自定客户端无掉落表，按 BeiDou 现有掉落/奖励标准自行配置。

建议落地步骤

  • ① 先迁资源，不碰逻辑：30 张地图 + 14 怪 + 17 NPC（客户端 Mob/Npc + 服务端 XML + wz-zh-CN 中文树名字）。
  • ② 导任务链：1340 + 31330–31355，按现有导入规范，Say 留空。
  • ③ 写 1 个 event 脚本：照 CWKPQ.js / LudiPQ.js 骨架，把「手臂 → 体内 → 心脏」三段推进写进去；凡是 mobTime=0 的图，必须 eim.schedule(fn, 5000) + map.instanceMapRespawn()。
  • ④ 配 Boss：8800400（5700 万 HP / Lv165）按 BeiDou 现有 Boss 方式配技能与掉落。
  • ⑤ 实测三件事：ft=6 骑乘图、心脏房用哪一张、手臂阶段判定。
  • ⑥ 验收：!debug mobsp / !debug map（gm5），改脚本用 !reloadevents。

逐图解析 life 的结果：怪物实例 0、怪物种类 0，只有 17 个 NPC。也就是说地图只是空白场地，刷什么怪、掉什么、怎么推进，全在 Roguelike 系统里（服务端 + 专属 UI）。这与岩壁巨人完全相反——岩壁巨人每张狩猎图都老老实实摆了 12–23 只怪。

2.4 为什么不能完整迁移

依赖083 端BeiDou 服务端说明
遗物（artifact）系统与选择界面无无局内成长核心：String/Redmoon.img 里每个遗物都有独立效果（最大体力/攻速/暴击/护盾…），需要一套 buff 装配与 UI。
Roguelike 局内技能无无Skill/Roguelike/Skill/Redmoon，194 条。
坦克载具（Redmoon_Tank）无无Etc/RoguelikeRiding，083 端无载具系统。
红月专属 UI / 特效 / Reactor无—UIRedmoon.img、Effect/Redmoon*、RoguelikeReactor/Redmoon。
等待队列入场 / 场次分配无无Redmoon_EnterMapByWaitQueue，需要排队与实例调度。
每周排名与奖励无无505076 領取每週排名獎勵——需要排名结算系统。
如果硬要做：工作量不是「迁一个副本」，而是「从零实现一个 Roguelike 模式」（局内状态机 + 遗物系统 + 载具 + 排名 + 一整套 273 UI）。可剥离复用的只有：104 张地图美术（可改做普通狩猎场/活动场）、17 个 NPC（9402xxx）、红月主题的背景与物件素材。但做出来的东西不是紅月之森。
