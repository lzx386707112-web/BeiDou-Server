# 神秘河完整依赖同步包

本目录包含当前项目中 158 张神秘河地图的完整依赖闭包，而不只是本轮修改文件：

- 客户端：地图、Map 资源、MapHelper、怪物、NPC、BGM、任务、任务物品及
  Map/Mob/Npc/Etc String。
- 服务端：地图、怪物、NPC、任务、任务物品、两套 String XML、怪物掉落数据库
  迁移，以及已存在的相关 NPC/传送脚本。
- 维护工具：迁移、旧端连接节点修复、消亡旅途资源隔离和完整审计脚本。

## 正确使用方式

1. 将 `Client/Data` **合并覆盖**到当前完整项目的 `clien/Data`。
2. 不要删除项目中原有的非神秘河文件。
3. 从合并后的完整项目分别重新打包 `Map.wz`、`Mob.wz`、`Npc.wz`、
   `Sound.wz`、`String.wz`、`Quest.wz` 和 `Item.wz`。
4. 七个 WZ 一起更新。只更新 `Map.wz` 会导致新地图引用的 BGM、怪物、NPC、
   任务物品或字符串资源在客户端中缺失。
5. 将 `Server` 合并覆盖到项目的 `gms-server`，然后重启服务端。
6. 确认 Flyway 已执行 `V2.1.42`；否则怪物不会产生新增掉落。

## 重要说明

这个同步包是“神秘河完整依赖闭包”，仍然不是整个游戏所有区域的完整 Data。
不能直接把本目录中的局部 `Client/Data/Map` 单独打成 `Map.wz` 后替换正式客户端；
那样会丢失其他区域原有地图资源。必须先覆盖到当前完整项目，再从完整项目打包。

本次闭包审计结果：189 张地图、96 个怪物、224 个 NPC、19 首 BGM、
31 个地图资源文件。三张啾啾剧情图及真香岛新增依赖的定向契约为
`errors=0 warnings=0`；全量审计仍会报告用户已有 `450002011-450002015/swimArea`
五项兼容规则差异。

本轮任务与掉落扩展审计：69 个啾啾/真香任务、19 个任务物品、12 种真香岛
怪物基础掉落；NPC、怪物、物品、前置与 signed-16 任务号依赖 `errors=0`。

84 种地图实际怪物的客户端与服务端 `info/eva` 已统一为 `100`，避免现代
`EVA 205–930` 在旧端造成 999 命中仍大量 MISS；其他怪物属性和动画未改动。

啾啾村左侧第一张地图 `450002011` 使用旧端水下世界的 `info/swim=1`，角色
掉入下层水域后可以跳跃游泳返回平台；地图地形、VR 边界和传送点未修改。

啾啾村 `450002000` 的紫绿装置原本依赖现代 `skyWhale/sky1` 上升气流，把角色
从 `(2475,-421)` 推送到 `(2475,-925)`，接近上层 `out04` 光洞。旧端不支持
`skyWhale` 控制器，因此参照自由市场气流，将原起点投影成 `pt=3` 同地图碰撞
传送，并直接以平台上的既有 `out04(2482,-950)` 作为目标；原有 Portal、地形、
对象及绳索记录均保持不变。

莫拉斯城镇 `450006130` 以实机不崩版本为二进制兼容底座，从当前 TMS 源重新
迁入 16 个已隔离验证的静态结构对象：11 个 `foothold_Bridge2`、4 个
`foothold_Castle` 和 1 个 `stone/7`；加上原有 6 个旧端 `connect` 对象，共

`tool/scripts/migration/migrate_morass_450006130.py`。

其余对象的兼容研究使用独立生成器
`tool/scripts/migration/build_morass_450006130_compat_experiment.py`，不会覆盖上述
正式地图。实验把 TMS 对象指向地图专用 `morassTownLegacy.img`，Canvas 像素与
ARGB4444 载荷保持不变，只保留旧端 `origin/z/delay` 元数据，并将每层 `zM`
按原相对顺序稠密化。A 版先恢复除 14 个 `foothold_Bridge` 外的 72 个缺失对象；
A 版实机正常后，B 版再补齐全部 14 个问题桥。该投影在通过真实旧客户端进图、
反复切图和 CPU 负载验证前，不得替换正式 22 对象版本。

## 450001014 稳定性说明

`450001014` 独占使用的怪物 `8641002` 带有 `firstAttack=1`。现代源把远程攻击
元数据放在 `info/attack/0`；原迁移器删除这个现代节点时，没有先把旧端仍需要的
`type=2` 和 `bulletSpeed=300` 投影到 `attack1/info`。结果是地图和怪物能够短暂
显示，但首次远程攻击初始化时缺少旧端契约字段并崩溃。兼容投影现在固定
`attack1/info` 为 `range, ball, hit, type, attackAfter, bulletSpeed`。

现代攻击动画原本还缺少第 `10` 帧。第 `9` 帧的相同 ARGB4444 载荷会继续用于
补齐 `10`，帧顺序固定为 `0-15`，并保留旧端已验证的
`attack1/info/hit/attach=1`。实机证明仅补帧不能消除本次闪退，因此缺帧属于独立
兼容性修正，不再记作该闪退的根因。

同类检查覆盖当时神秘河地图实际引用的 `83` 个怪物。现代源共有 `92` 条攻击定义，
其中 `12` 条同时满足 `type=2`、存在 `bulletSpeed`、并有对应旧端 `ball` 节点：
`8641002`、`8642012-8642015`、`8642021-8642022`、`8644001`、`8644005`、
`8644007-8644008`、`8644010`。这些怪物全部带 `firstAttack=1`，现在统一把源值
投影到对应的 `attack1/info` 或 `attack2/info`；`8642012-8642022` 使用
`bulletSpeed=400`，其余使用 `300`。每个既有客户端 IMG 通过原始记录级补丁仅增加
`type` 和 `bulletSpeed`，不重编码动画、弹体或命中特效。

路线所需的 `450001219`、`450001230`、`450001240`、`450001250`，怪物
