# Boss-only 兼容迁移结论与顺序

来源客户端：`/Users/lizixian/Documents/mxd/神说/Data`。

本批迁移只包含 Boss 本体、阶段形态、Boss 技能视觉和合理的伤害/状态效果，不迁地图、副本入口、奖励和原版地图机关。目标不是把高版本节点原样塞进旧客户端，而是保留 Boss 观感并建立旧客户端能够稳定运行的兼容闭环。

## 完成标准

- Boss 可以反复召唤、受击、击杀和清理，不在召唤、放技能或阶段切换时崩溃。
- 保留 `stand/move/hit/die/attack/skill` 中有价值且可兼容的动作。
- Boss `info/skill`、客户端 `MobSkill.img`、服务端 `MobSkill.img.xml`、`MobSkillType` 和 `skillN` 动作必须对齐。
- 旧客户端不支持的 `screen`、新版场景对象和地图机制改成 `Map/Effect.img/customBoss/...`，由服务端广播视觉并按命中帧延迟结算。
- 只为更换 Boss 外观保留阶段切换；删除月光槽、恐惧值、日夜计量、地图谜题、锁血验伤和平台机关等副本机制。
- 高血量只写入服务端 long `maxHP`；客户端 Mob IMG 保持 int 安全值。
- revive、召唤物、Boss 血条、String/Mob 和旧服务端必读攻防字段必须闭环。

## 全屏技能兼容方案

沿用阿卡伊勒漩涡的已验证路径：

```text
Boss 选择技能
  -> 播放可兼容的 Boss 动作
  -> PacketCreator.showEffect("customBoss/<boss>/<skill>")
  -> 等待视觉命中帧
  -> 服务端结算全屏、区域或安全区伤害
```

全屏 Canvas 放在 `clien/Data/Map/Effect.img`，不放 `Effect/BasicEff.img`，也不把 `screen` 镜像到普通角色/怪物 effect 层。大画布优先转为 ARGB4444，降低旧客户端首次解码和内存压力。

## 可以删除或降级的机制

- 麦格纳斯：地图边缘毒区、原版陨石对象管理和地图边界惩罚，可改为定时区域攻击。
- 露希妲：梦境蝴蝶计数、石像条件、强制地图切换和锁血规则；保留龙、弹幕和爆发视觉。
- 威尔：月光槽、镜面空间、验伤和锁血解谜；保留阶段外观、主要攻击和全屏视觉。
- 塞伦：日夜时间轴、圣剑计量、正午门槛和原地图安全区；保留光束、圣剑和爆发视觉。

## 威尔迁移口径

神说和当前项目均有 `8880300/8880301/8880302/8880305/8880315`。主阶段链为 `8880300 -> 8880301 -> 8880302`：

- `8880300`、`8880301` 保留所有经过兼容清洗的主要攻击动作。
- `8880301` 只保留客户端和服务端已有的老 MobSkill。
- `8880302` 声明 `242/9~11`，但神说 `Skill/MobSkill.img` 没有这些等级，本体也没有对应 `skill1/2/3` 动作，不能原样启用；必须删除断裂引用或改成服务端驱动的兼容视觉技能。
- `8880305/8880315` 作为威尔相关辅助实体一起审计，但不默认引入地图谜题。
- 阶段切换只负责更换外观，不恢复月光、镜面、验伤或锁血机制。

具体落地和实测结果继续记录在本文件，避免把“文件存在”误写成“技能闭环完整”。

## 露希妲迁移结果

神说露希妲资源使用 EMS key，迁移时必须解码 Canvas 后重新写成 BeiDou/GMS key，不能直接复制 `.img`。Boss-only 第一版落地为主阶段链 `8880140 -> 8880141 -> 8880142`，并一并补入 `8880161/8880165/8880171/8880175` 石人和蝴蝶辅助实体资源，供后续技能视觉/召唤兼容使用，但不恢复梦境蝴蝶计数、石像条件、强制切图和锁血规则。

参数与兼容处理：

- 客户端三个主阶段 `maxHP=2000000000`，保持旧客户端 int 安全。
- 服务端三个主阶段均使用 `<string name="maxHP" value="5000000000"/>`，三阶段总有效血量约 150 亿。
- 恢复 `8880140 -> 8880141 -> 8880142` revive 链；`8880142` 不再 revive。
- 保留所有当前客户端、服务端和 `MobSkillType` 都能闭环的 Boss 技能，共 10 个：
  - `8880140`：`145/2`、`128/16`、`131/13`
  - `8880141`：`145/5`、`145/2`、`128/16`、`125/9`
  - `8880142`：`145/2`、`126/2`、`128/10`
- 源端 `186/8`、`201/60` 当前双端 `MobSkill.img` 均缺失；`201` 还超出现有服务端 `MobSkillType` 支持范围，因此第一版不启用。
- 对技能表指向但源端缺失的 `skillN` 动作，复用相近的 `attack/skill` 动作补齐，保证客户端收到技能动作编号时有可播放资源，服务端 XML 同步。
