# Boss-only 兼容迁移结论与顺序

来源客户端：`/Users/lizixian/Documents/mxd/神说/Data`。

本批迁移只包含 Boss 本体、阶段形态、Boss 技能视觉和合理的伤害/状态效果，不迁地图、副本入口、奖励和原版地图机关。目标不是把高版本节点原样塞进旧客户端，而是保留 Boss 观感并建立旧客户端能够稳定运行的兼容闭环。

## 完成标准

- Boss 可以反复召唤、受击、击杀和清理，不在召唤、放技能或阶段切换时崩溃。
- 保留 `stand/move/hit/die/attack/skill` 中有价值且可兼容的动作。
- Boss `info/skill`、客户端 `MobSkill.img`、服务端 `MobSkill.img.xml`、`MobSkillType` 和 `skillN` 动作必须对齐。
- 旧客户端不支持的 `screen`、新版场景对象和地图机制改成 `Map/Effect.img/customBoss/...`，由服务端广播视觉并按命中帧延迟结算。
- 只为更换 Boss 外观保留阶段切换；删除月光槽、恐惧值、日夜计量、地图谜题、锁血验伤和平台机关等副本机制。
- 高血量只写入服务端 long `maxHP`；客户端 Mob IMG 保持 int 安全值。
- revive、召唤物、Boss 血条、String/Mob 和旧服务端必读攻防字段必须闭环。

## 全屏技能兼容方案

沿用阿卡伊勒漩涡的已验证路径：

```text
Boss 选择技能
  -> 播放可兼容的 Boss 动作
  -> PacketCreator.showEffect("customBoss/<boss>/<skill>")
  -> 等待视觉命中帧
  -> 服务端结算全屏、区域或安全区伤害
```

全屏 Canvas 放在 `clien/Data/Map/Effect.img`，不放 `Effect/BasicEff.img`，也不把 `screen` 镜像到普通角色/怪物 effect 层。大画布优先转为 ARGB4444，降低旧客户端首次解码和内存压力。

### 技能调度修复

实测发现旧服务端只随机抽取一个技能候选，候选处于冷却、反射已生效或条件不满足时会直接放弃本轮；同时 `LifeFactory` 按技能表序号读取 `skillN` 动画，没有使用声明中的 `action`。黑魔法师每阶段状态技能较多且多个声明复用动作，因此会表现为长期只释放一个技能，`178~182` 全屏及召唤技能几乎不触发。

- `LifeFactory` 改为读取声明的 `action`，按实际 `skillN` 计算动画延迟。
- `Monster` 返回打乱后的完整技能候选列表。
- `MoveLifeHandler` 逐个筛选候选，直到找到满足冷却、HP 和 MP 条件的技能。
- 整合补丁必须包含 `LifeFactory.java`、`Monster.java` 和 `MoveLifeHandler.java`，覆盖后重新编译并清理服务端 WZ/XML 缓存。
