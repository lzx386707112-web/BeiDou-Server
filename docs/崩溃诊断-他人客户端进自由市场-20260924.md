转储侧确认（我直接从 `.dmp` 里读的，不信日志文本）：

## 四、根因判断（结论 + 不确定度）

**根因家族：媒体/Flash 载入失败 → 后续渲染路径拿着一个"非空但已失效"的影片指针继续调用 → 控制权落到垃圾地址。**

依据：

* 崩溃前 0.3 秒是 `_com_error`（E_NOINTERFACE）风暴，抛点栈帧、`ebx` 与历史两次已修 bug **完全同族**；
* AV 现场寄存器与本项目 flash guard 的 `jmp *%eax`（eax=RenderFlash、esi=影片）逐一对齐；
* 本项目早已记录：这个客户端的媒体/Flash 资源本身就是缺的（`_com_error hr=0x80030002 STG_E_FILENOTFOUND`），
  之前两次补丁只是**让失败不再抛异常/不再二次崩**，**没补资源**；
* 现有 guard 只校验"影片槽地址仍属于 WzFlashRenderer 映像"（`VirtualQuery` + `Type==MEM_IMAGE` + `AllocationBase==g_mod`），
  **不校验 `*槽` 这个影片指针本身是否有效** → 非空野指针会原样透传进渲染器。

**尚未闭环**：`0x148B6640 / 0x148B66B0` 这两个地址"为什么正好落在全零页"，只能确定是"跳进垃圾"，还没拿到**发起这次跳转的指令**。
两处 EIP 的低 16 位恰好等于 WzFileLogger 桩 RVA（0x6640=STUB_A、0x66B0=CAVE_C），但内存里没有第二份 DLL 拷贝，
所以现在还不能断言"地址算错基址"。要给结论就必须补观测（见下）。
