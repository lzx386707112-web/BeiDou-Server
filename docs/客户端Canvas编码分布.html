数据来源：用 tool/wz-python 逐个解析 clien/ 下全部 53,915 个 .img 的真实属性树，统计每个 Canvas 节点的 format/format2。生成时间 2026-09-29。

结论：有，而且 ARGB8888 是客户端的主流编码（占 82.9%）。 它不是迁移引入的，而是客户端原生数据：本仓库最早的客户端提交（0119c8d8a6，2025-09-20「魔改客户端上传资源」） 中抽样的技能 / 怪物 / 地图物件文件就是 100% ARGB8888，且至今未改动过的那批仍是 ARGB8888。 因此老客户端本来就能渲染 ARGB8888，它本身不构成兼容性风险。
但项目的 ARGB4444 规范确实被执行了：迁移新增的画布全部是 ARGB4444。 以 Data/Skill/232.img（主教）为例——新增 880 个画布 全部为 ARGB4444；41 个原 ARGB8888 画布被替换成 ARGB4444（同时尺寸也变了，属重做而非单纯转码）； 保留的 569 个 ARGB8888 全部是未改动的原版数据。
