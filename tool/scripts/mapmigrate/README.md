# 地图 / Boss 迁移兼容性工作台

启动：

```bash
rtk tool/scripts/mapmigrate/start-mapmigrate.sh
```

默认地址为 `http://127.0.0.1:8770`。

## 当前可靠能力

- 读取旧客户端 GMS IMG、现代散装 IMG，或经 MSProbe 提取的新客户端 MS 条目；
- 展示完整节点路径、类型、标量值、节点含义和兼容性规则结果；
- 将迁移源与兼容底座按完整路径逐节点对照；
- 在对照表中同时显示迁移源与兼容底座各自的兼容状态，无需逐个打开详情；
- 区分相同、值变化、仅迁移源和仅底座节点；
- 直接标出节点所属的现代容器和现代资源，例如 `现代节点 flip`、`现代资源 纹理 2050/0`；
- 对 Canvas 比较尺寸、格式、原点、子整数和压缩像素 SHA-256；
- 审计真实纹理尺寸、像素数、压缩载荷、ARGB4444/RGBA/POT 内存估算和单边 2048 上限；
- 对超限纹理计算等比目标尺寸、缩放比例和新原点，并提供原图/2048/1024/512 预览；
- 在详情区同时预览迁移源与底座 Canvas；
- 导出包含节点对照的 Markdown / JSON 报告；
- 清洗预演（不写盘）。

节点详情可以通过表格双击或“放大”按钮在弹窗中查看；清洗预演和报告集中在
“操作与报告”弹窗中。MS 条目使用独立搜索弹窗，未搜索时只显示前 100 个条目，
搜索后最多显示 500 个匹配项，避免大包一次创建数千个页面节点。窄屏时内嵌详情栏
会收起，可通过底部“放大节点”或双击表格节点在弹窗中查看完整详情。
中等宽度下也会优先保留节点树和完整对照表，把详情移入弹窗；原因与建议使用固定
列宽并自动换行，避免长规则文本挤占路径和状态列。

## 现代数据判断与 MS 资源链

现代节点规则按证据分级：明确不受旧端支持的结构标为“不兼容”，已知现代但需要
底座或服务端上下文决定投影方式的字段标为“现代”或“待审”。规则不会再用
`fieldLimit >= 1048576` 之类的宽泛阈值推断版本；例如已经在旧端验证过的
`fieldLimit=1909496` 会保留。除少数有固定安全转换的字段外，现代/不兼容节点也不会
自动删除。

现代性标签与兼容结论相互独立：节点可能本身满足旧端标量契约，但仍位于现代容器
（如 `flip`）中，或引用现代纹理/外链资源。现代容器标签会继承到其子节点；Canvas
外链解析出真实 `_Canvas` 后会按真实格式重新标记资源。界面的“现代”筛选同时包含
规则状态为现代的节点，以及来源或底座带有任一现代节点/资源标签的节点。

当前 TMS `.ms` 包主要提供 Mob/Skill 元数据。Canvas 真正像素通常位于
`MapleStory-IMG/Data/<分类>/_Canvas/*.img`，工具会先在该散 IMG 目录精确查找，找不到
时才跨 `.ms` 包查找并提取。由 `_outlink` 指向的真实 Canvas 已可自动解析和预览；
这些链接本身仍会标记为需要物化到旧端结构的不兼容节点。现代 Map 数据通常来自散
IMG，而不是当前的 Mob/Skill `.ms` 包；直接选择地图散 IMG 时，工具也会自动衔接
同目录的 `_Canvas/<同名>.img`。

## 纹理审计与降级预演

每个 Canvas 详情会优先使用已解析的真实 `_Canvas` 像素，而不是主 IMG 中的 1×1
占位，显示以下指标：

- 实际宽高、像素数和 WZ 压缩载荷；
- ARGB4444 理论占用（2 B/px）和 RGBA 解码占用（4 B/px）；
- 宽高向上取 2 的幂后的保守纹理占用估算；
- 是否超过已验证的旧端单边 2048 上限；
- 超限时保持宽高比的 2048 内目标尺寸、缩放比例和同比例新原点。

详情中的“原图 / ≤2048 / ≤1024 / ≤512”只使用 Lanczos 生成浏览器 PNG 预览，并可
下载当前预览 PNG，不会修改 IMG。JSON/Markdown 报告会保存纹理汇总和逐 Canvas 投影
参数。正式降级时除了像素，还必须按横纵缩放比例同步修改 `origin`、`lt`、`rb`、
`head` 等坐标；`delay` 保持不变。总纹理内存没有设置伪造的硬阈值，因为它还取决于
客户端纹理缓存、场景同时驻留资源和显卡能力，目前只提供可比较的估算值。

解析出现截断或警告时，工具会拒绝继续，避免把不完整节点树误判为兼容。

## 写盘安全边界

现有清洗、删除和复制代码依赖 `encode_image_body()` 整树序列化，不能证明旧客户端
二进制布局稳定，因此生产写入默认关闭。界面中的删除、复制按钮会禁用，清洗只允许
预演。

环境变量 `MAPMIGRATE_UNSAFE_FULL_REWRITE=1` 只用于明确接受整树重写风险的临时实验，
不代表产物符合项目交付标准，也不能用于交付目录。

## 距离“自主完成地图 / Boss 迁移”还缺什么

工具目前是可信的分析与对照工作台，不是完整迁移器。完整闭环至少还要依次接入：

1. 迁移清单：目标 ID、来源条目、兼容底座、允许变化节点和依赖资源；
2. 资源解析：Map 的 Back/Obj/Tile/Life/NPC/Reactor/Portal/脚本依赖，以及 Boss 的
   动作、攻击、MobSkill、声音、链接与服务端行为；
3. 兼容投影：把现代结构投影到已验证的旧端结构，Canvas 统一为 GMS ARGB4444；
4. 安全生成：新文件可以完整生成；已有文件必须使用同长原位或原始属性记录替换；
5. 客户端与服务端同步：IMG、XML、脚本、Java 常量/处理器、传送与刷新逻辑；
6. 验证流水线：解析警告、Canvas 解码、依赖闭包、临时 WZ 打包回读、生成器幂等、
   原始记录边界、服务端构建和针对性契约测试；
7. 交付：只复制通过全部离线门禁的运行文件并校验 SHA-256。

在这些阶段完成前，不应把“规则全部兼容”解释为“地图或 Boss 已迁移完成”。
